# AI画像クイズ出題プール拡張 実装レビュー

## 結論

現在の `feature/ai-image-quiz-pool-expansion` には、コミット `c655ca7` 相当の両ゲーム本体と既存画像が復元済みである。したがって、ゲームフローや通信を作り直さず、次の範囲に限定するのが最小かつ安全である。

1. 実写25枚を選定・保存し、出典メタデータを追加する。
2. 対応する偽物25枚と表情27枚を生成・保存する。
3. `PAIR_BANK` と `EXPRESSION_BANK` に添付どおりのエントリを追加する。
4. テストの件数期待値を30へ変更し、資産との対応検査を追加する。
5. `.agents/ai-image-quiz-games-plan.md` に出典と全生成プロンプトを記録する。
6. Nodeテストとブラウザ2タブ確認を行う。

`ROUND_TOTAL`、抽選、正誤判定、得点、通信、HTML、CSS、`net.js` は変更しない。既存の `PAIR_BANK` 5件、`EXPRESSION_BANK` 3件と既存画像も維持する。

## 推奨実装順

### 1. 実写候補を先に確定する

- 添付指定の11カテゴリから合計25枚をOpenverseで探す。
- API検索条件は `license=cc0,pdm` とし、採用時に各レコードのライセンス値と原典ページを再確認する。
- 幅800px以上を目安にし、一般向け・AdSense掲載サイトに不向きな生々しい標本、死骸、医療画像などを除外する。
- 既存5枚と内容が極端に重ならず、「奇妙だが一般向け」の幅が出るようカテゴリを分散する。
- 採用順を確定してから `06_<slug>.jpg`～`30_<slug>.jpg` を割り当てる。途中で番号を再利用しない。

### 2. 実写を正規化して保存する

- 保存先は `real-or-fake-photo/assets/real/`。
- 拡張子だけを書き換えず、画像を実際にJPEGへ変換する。
- EXIFの向きを反映し、RGB JPEG、長辺1200px程度、品質80～85程度へ揃える。
- ゲーム側は `object-fit: cover` を使うため、元画像の構図を壊す過度な事前クロップは避ける。
- `metadata.json` は新規25件も既存形式に揃え、最低限 `title / creator / license / source / image_url / width / height` を保持する。`source` はクレジット表示用の原典URL、`image_url` は取得元画像URLとして区別する。

### 3. 偽物画像を対応実写ごとに生成する

- 新規実写を視覚参照にして、構図、被写体サイズ、視点、照明、背景、色調、被写界深度を寄せつつ、存在しない生物・物体へ置き換える。
- 保存先は `real-or-fake-photo/assets/fake/06_<slug>.jpg`～`30_<slug>.jpg`。実写と同じベース名にする。
- 実写と同じJPEG正規化を行い、解像度、圧縮、アスペクト比、彩度などが「AIか否か」の手掛かりにならないようペア単位で比較する。
- 既存の1～5は完成資産なので再生成しない。

### 4. 表情画像を生成する

- 添付の `pattern-04`～`pattern-30` の27プロンプトを正本として使う。
- 保存先は `expression-quiz/assets/faces/pattern-04.jpg`～`pattern-30.jpg`。
- 顔のクローズアップ、無地背景、線画＋平坦色という共通スタイルを揃える。
- 添付本文のシナリオと記録用プロンプトは校正せず、そのまま保持する。「平坂色」は誤記と思われるが、記録では原文を維持し、生成時の解釈だけ「平坦色（平塗り）」と補う。
- 既存 `pattern-a`～`pattern-c` は再生成・改名しない。

### 5. データバンクと文書を更新する

- `real-or-fake-photo/logic.js`
  - `pair-06`～`pair-30` を追加する。
  - 各項目の `realImage`、`fakeImage`、`credit` をメタデータと完全一致させる。
- `expression-quiz/logic.js`
  - 添付の27件を文言変更なしで追加する。
  - `id` と画像名はゼロ埋めされた `pattern-04`～`pattern-30`。
  - 各項目は正解1件、誤答3件を持つ。
- `.agents/ai-image-quiz-games-plan.md`
  - 新規25実写のクレジット表。
  - 新規25偽物の番号・ファイル名・生成プロンプト。
  - 添付の表情27件（ID、ファイル名、性別、正解、誤答3件、生成プロンプト）。
- シナリオ文は通信上の回答値でもあるため、句読点・空白を含め添付から不用意に変更しない。

## データ検証

既存の件数アサーションを両方30へ変えるだけでなく、次を機械検証するのが安全である。

### 偽物鑑定

- `PAIR_BANK.length === 30`
- IDが一意で、集合が `pair-01`～`pair-30`
- `realImage` と `fakeImage` が各30件一意
- バンクが参照する60ファイルがすべて存在する
- `assets/real/` と `assets/fake/` に余剰・欠番がない
- 全画像がJPEGとしてデコードでき、幅・高さが正数
- 全 `credit` に非空の `title / license / source` がある。作者不明は既存同様 `creator: null` を許可
- `license` は小文字へ正規化した `cc0` または `pdm`
- `metadata.json` が30件で、各実写ファイルと同じ順序・情報に対応する
- `logic.js` の `credit` と `metadata.json` の `title / creator / license / source` が一致する

### 表情当て

- `EXPRESSION_BANK.length === 30`
- IDが一意で、既存 `pattern-a`～`pattern-c` と `pattern-04`～`pattern-30` の集合に一致
- 各画像ファイルが存在し、JPEGとしてデコードできる
- 各項目に非空の正解文と、ちょうど3件の非空誤答がある
- 全120シナリオ文が重複しない
- 各項目内の4択も重複しない
- 新規27件の性別指定が女性14件・男性13件で、プロンプト記録と画像の見た目が対応する
- `ROUND_TOTAL === 3` が維持される

ファイル存在検査は `test.js` から `node:fs` と `node:path` で行える。JPEGの厳密なデコード検査はテストに画像ライブラリを持ち込まず、資産準備用の検証スクリプトまたは既存環境の画像ツールで別途行うのが、このリポジトリの依存なし方針に合う。

## 画像品質方針

正式成果物にはAI生成画像を使用し、プレースホルダーは原則採用しない。プレースホルダーはファイル配線を確認できても、偽物鑑定では即座に答えが分かり、表情当てでは表情品質を検証できないため、完了条件のブラウザ品質確認を満たさない。

やむを得ず暫定使用する場合は次を守る。

- ファイル名と寸法は本番と同じにする。
- 感情名、正解文、「REAL」「FAKE」など答えを漏らす文字を入れない。
- `pattern-04` のような非意味的IDだけを表示する。
- 計画書と引き継ぎに「暫定」を明記し、完成扱いにしない。

生成後は一覧だけでなく、偽物鑑定は各実写・偽物を横並びで、表情当ては30枚のコンタクトシートで目視する。特に文字・透かし・ロゴ、破綻した顔や手、不適切表現、極端な画質差、構図だけで正解が分かる偏りを確認する。
