# 偽物鑑定ゲーム 出題プール拡張の調査

## 調査対象

- ユーザー添付の「偽物鑑定ゲーム/表情当てクイズ 出題プール拡張」指示
- 直前実装コミット `c655ca7` の `real-or-fake-photo/`
- 現在の作業ディレクトリにある実写素材と `.agents/ai-image-quiz-games-plan.md`

## 現状

直前実装 `c655ca7` ではゲーム本体は完成済みで、`PAIR_BANK` は `pair-01`〜`pair-05` の5件、`ROUND_TOTAL` は5である。各エントリは次の形を持つ。

```js
{
  id,
  realImage,
  fakeImage,
  credit: { title, creator, license, source }
}
```

既存ロジックのうち、今回そのまま利用できるものは以下。

- `selectRoundPair` は `usedIds` にない問題を優先し、全件消化後だけ履歴をリセットする。バンクを30件へ増やしても変更不要。
- `buildRoundPayload` は本物を左右どちらへ置くかランダム化する。変更不要。
- `allImagePaths` はバンクから本物・偽物双方の許可パスを動的に作るため、エントリ追加だけで新画像も許可対象になる。
- `script.js` は `L.PAIR_BANK` と `L.ROUND_TOTAL` を参照しており、固定5件を前提とする箇所は見当たらない。
- 出題メッセージには画像パスだけを含め、`credit` と `correctIndex` は結果発表時までホスト側に保持する設計が維持されている。

既存テストはバンク件数を5件と固定しているほか、ID重複、必要パス、クレジット、抽選の未出題優先・リセット、左右ランダム化、全画像パス列挙を検証している。

現在のワークツリーでは調査時点で `real-or-fake-photo/assets/real/` の既存5枚と `metadata.json` のみが見えており、ゲーム本体と既存偽物5枚は直前コミット側に存在する。実装前に `c655ca7`（または `feature/ai-image-quiz-games`）の内容を現在の作業ブランチへ取り込む必要がある。なお添付指示に記載された旧worktreeを新たに使うのではなく、現在の共有作業ディレクトリとブランチで作業するのが安全。

## 添付指示とのギャップ

1. `PAIR_BANK` が5件で、要求は30件。`pair-06`〜`pair-30` の25件が不足。
2. 実写画像は既存5枚のみ。11カテゴリから選ぶ新規25枚と、そのクレジットメタデータが不足。
3. 偽物画像は直前コミットに既存5枚のみ。新規実写に対応する25枚が不足。
4. 新規25件の偽物画像生成プロンプトが未作成。
5. `test.js` の件数アサーションが5のまま。
6. `.agents/ai-image-quiz-games-plan.md` は既存5件の出典・プロンプトしかなく、新規25件の表とプロンプトが不足。
7. 指示の完了条件にあるブラウザ複数ラウンド確認が未実施。

## 必要変更

### 素材調達

- Openverse APIを使い、指定11カテゴリから合計25件を採用する。
- 各候補について `license` が `cc0` または `pdm`、幅がおおむね800px以上、一般向け広告サイトで問題のない内容であることを確認する。
- Openverseの検索結果に含まれるライセンス値だけでなく、可能なら原典ページも確認する。ダウンロードURLとクレジット用 `source` は区別する。
- 実写を `assets/real/06_<slug>.jpg`〜`30_<slug>.jpg` として保存する。レスポンスがPNG等の場合も、拡張子だけを変えず実際にJPEGへ変換する必要がある。
- `metadata.json` に新規25件も追記すると、コードとドキュメントの転記元を一元化できる。

### 偽物画像

- 実写ごとに構図・照明・背景・被写体スケールを寄せた、日本語の生成プロンプトを1件作る。
- 実写と同じベース名で `assets/fake/06_<slug>.jpg`〜`30_<slug>.jpg` を配置する。
- 本生成ができなければプレースホルダーでも指示上は許容される。ただしプレースホルダーではゲームとしてのブラウザ品質確認は限定的になるため、その旨を記録する。

### コード・文書

- `logic.js` の `PAIR_BANK` に25件を追加し、IDは `pair-06`〜`pair-30` とする。
- `ROUND_TOTAL = 5` は変更しない。
- `test.js` の件数期待値のみ30へ変更する。
- `.agents/ai-image-quiz-games-plan.md` に、新規25件のクレジット表と偽物生成プロンプト一覧を既存形式で追記する。

## 実装時の注意

- `credit.creator` は既存5件では `null` も許容される。テストも `title` と `source` のみ必須。ただし新規素材では取得できるなら creator と license を必ず保存する。
- ファイル名、`realImage`、`fakeImage`、メタデータ、文書の番号とスラッグを完全一致させる。
- 同じ画像、同じ原典、同じIDの重複を避ける。
- 実写と偽物の画像寸法・画質差が露骨だと正解の手掛かりになる。JPEG形式、概ね同程度の解像感に揃える。
- 画像URLを直接ゲームから参照せず、必ずローカルアセットとして保存する。
- 新規画像の内容だけでなく、クレジットの外部リンクがHTTPSか、意図した原典へ到達するかも確認する。

## テスト観点

### Nodeテスト

- `PAIR_BANK.length === 30`
- 全IDが一意で `pair-01`〜`pair-30` が揃う
- `realImage` と `fakeImage` が非空かつ異なる
- 全画像パスが一意で、対応するファイルが実在する
- `credit.title`、`credit.license`、`credit.source` が妥当。licenseは新規分について `cc0` / `pdm`
- `selectRoundPair` が5ラウンド内で重複を出さない
- 30件を使い切るまで重複せず、31回目で履歴がリセットされる
- `ROUND_TOTAL === 5` が維持される
- `allImagePaths().length === 60`
- `node real-or-fake-photo/test.js` が `All tests passed`

既存テストはファイル実在性、ライセンス値、画像パス重複までは検査しないため、今回追加すると素材転記ミスを早期検出できる。

### ブラウザ確認

- ホスト＋ゲストの2タブで開始し、5ラウンド完走できる
- 新規画像が404や破損表示にならない
- 左右の画像が毎回表示され、選択ボタンと正解ハイライトが崩れない
- 同一プレイの5問で同じペアが再出題されない
- 出題中にクレジットや正解位置がDOM・通信データへ漏れず、結果画面でのみ出典が表示される
- 出典リンクが別タブで正しい原典を開く
- モバイル幅でも画像の固定アスペクト比と選択操作が崩れない
- 複数回プレイして、新規25件が実際に抽選対象になる
